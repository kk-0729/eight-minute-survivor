# 8분의 생존

HTML과 JavaScript로 만든 단일 플레이어 브라우저 게임입니다. 원본은 `src/`이며,
빌드한 `dist/index.html`을 Chrome 또는 Edge에서 열 수 있습니다.

## 검사와 빌드

Node.js 22가 있으면 저장소 폴더에서 다음 명령을 실행합니다. 별도 패키지 설치는 필요 없습니다.

```powershell
node --test tests/game.test.cjs
node scripts/build.cjs
```

테스트는 브라우저 환경을 흉내 낸 가벼운 자동 검사입니다. 실제 브라우저에서의 화면,
프레임 속도, 장시간 플레이 밸런스까지 보증하지는 않습니다. 빌드는 `src/`만
`build-pages/`에 복사하고 `.nojekyll`을 추가하며, 로컬 실행용 `dist/`도 갱신합니다.
`build-pages/`는 생성물이며 Git에 포함되지 않습니다.

로컬 서버에서 확인하려면 빌드한 다음 `python -m http.server 8877 --directory build-pages`를
실행하고 브라우저에서 `http://127.0.0.1:8877/`을 엽니다.

## 전투 수치와 속성별 루트

세피리아의 공식 수치가 아닌 **8분의 생존 전용 설계**입니다. 원본은 `src/`이며,
밸런스 표는 `src/combat.js`의 `BUILD_ROUTES`에서 관리합니다.

- 기본 속성 공격력 20. 대검/석궁/지팡이 계수 1/0.66/0.8, 공격 간격 0.50/0.33/0.40초.
- 모든 무기의 1레벨 기본 단일 DPS는 방어력 0/전탄 명중 시 **40**입니다.
- 매 레벨업마다 **기본 공격력 +5%**가 자동 누적됩니다(기본값 대비 합연산).
- 레벨업 선택창에는 항상 **선택 속성 공격력 +1** 카드가 표시됩니다.
- 공격력 예: 18레벨에서 속성 공격력 +1을 4번 선택하면 `20 × (1 + 0.05 × 17) + 4 = 41`.
- 3레벨에 해당 속성의 루트 A/B 중 하나를 선택하고 게임이 끝날 때까지 잠급니다.
  6·10·14레벨에 해당 루트의 추가 피해 단계가 자동으로 올라갑니다.
- 다른 속성 카드와 물리 속성 선택은 숨깁니다. 공통 강화와 선택 속성 카드는 유지합니다.
- 원거리 투사체는 조준 시점에 기억한 목표 **좌표**로 직선 이동하고, 발사 후 추적하지 않습니다.
- 화면에 표시하는 피해 숫자는 반올림합니다. 내부 계산은 소수점 정밀도를 유지합니다.
- 직접 피해의 방어 감소율은 `clamp(0.445 × ln(1 + DEF / 40), 0, 0.9)`입니다.
- 중간보스 듄켈 1260 HP / 방어 50, 최종 보스 림보 4000 HP / 방어 50.
- 화상·상태이상, 감전·연쇄와 빌드별 추가 공격은 별도로 적용됩니다.
  단일 대상 수치는 빌드 효과를 실제 전투 루프에 넣은 통제된 시뮬레이션 결과입니다.

### 18레벨, 속성 공격력 +1 카드 4회 기준 보스 TTK

| 속성 | 루트 | 대검 | 석궁 | 지팡이 |
|---|---|---:|---:|---:|
| 화염 | A 지옥불 | 35초 | 43초 | 28초 |
| 화염 | B 태양의 심판 | 30초 | 34초 | 22초 |
| 얼음 | A 영원한 겨울 | 58초 | **70초** | 48초 |
| 얼음 | B 빙하의 무장 | 52초 | 65초 | 43초 |
| 번개 | A 초전도 | 23초 | 29초 | 18초 |
| 번개 | B 뇌신의 폭풍 | 21초 | 27초 | **16초** |

정지 보스, 사거리 내 플레이어, 치명타 0%, 추가 공격속도/투사체 강화 없음,
다른 몬스터 없음, 행동 중 회피 및 피격 없음이라는 조건입니다.
실제 플레이 결과는 이동·투사체 빗나감·다른 적 간섭에 따라 달라집니다.
자동 피해 시스템은 18가지 무기×속성×루트 계수와 일부 상태이상·광역 효과를
구현한 단계입니다. 세피리아식 개별 무기 진화 스킬의 서로 다른 애니메이션,
투사체 외형, 소환수 등은 아직 완성되지 않았습니다.

## 레벨업 선택과 세피리아식 아티팩트

레벨업할 때는 **4개 카드 중 하나**를 선택합니다. 첫 번째는 항상 '속성 공격력 +1'이고,
나머지 세 칸은 무기 전용·선택 속성 아티팩트·공통 강화 중 가능한 후보에서 뽑습니다.
1회 새로고침을 제공합니다. 이미 얻은 고유 아티팩트는 다시 나오지 않고,
해당 속성·해당 무기 및 최소 레벨 조건을 만족하는 카드만 등장합니다.
3레벨에 속성 루트 A/B 중 하나를 결정하고, 6·10·14레벨에는 새로운 전용 기술의
진화 방향을 두 가지 중에서 선택합니다. 진화 선택은 기본 레벨업 카드와 별개입니다.

- **공통 7종:** 속성 공격력 +1, 공격 간격 감소, 다중 공격(원거리 전용), 최대 HP/회복,
  이동속도, 자석 범위, 체력 회복.
- **화염 4종:** 붉은 뱀의 눈(좌표 지정 운석), 봉황의 깃털(추가 투사체),
  신갈나무 숯(화상 피해 주기 단축), 태양검(무기 적중 연계 불꽃 칼날).
- **얼음 4종:** 아이스 볼트(얼음 바늘 2개), 빙하의 메아리(범위 냉기),
  얼음 덩굴(적중 연계 가시), 얼어붙은 심장(동상 축적·빙결).
- **번개 4종:** 전격 차크람(범위 전격), 번개 화살(추가 탄환),
  천둥 귀걸이(인접 적 번개), 피뢰침(특수 공격 주기 개선).
- **무기별 2종:** 대검은 참격 사거리·검기 충격파, 석궁은 관통·연속 화살,
  지팡이는 범위 파동·메아리 구체.
- **루트별 추가 카드 2종:** 전용 기술의 범위 강화, 발동 주기 개선.

아티팩트 효과와 무기 계열은 세피리아의 **메커니즘에서 영감받은 자체 구현**입니다.
원작의 아티팩트 배치·MP 규칙·공식 능력치 및 그래픽을 그대로 재현하지 않습니다.
게임에서는 배치 없이 획득 즉시 발동합니다. 원거리 탄환과 보조 탄환은 발사 시의
적 **좌표**를 기준으로 쏘며 추적하지 않습니다. 운석도 미리 지정한 좌표에 떨어집니다.

**밸런스 범위:** 위 18개 보스 처치 시간은 속성 공격력 +1을 4회 선택한 상태에서,
추가 속도·무기·아티팩트 카드를 사용하지 않은 통제 전투입니다. 플레이어가 강력한
추가 카드를 선택하면 실제 처치 시간은 달라집니다. 스킬/시각효과도 아직 더 확장할 수 있습니다.

## 초반 몬스터 및 레벨업 밸런스

첫 120초의 일반 몬스터는 슬라임(11 HP), 파란 달팽이(12 HP), 빨간 달팽이(12 HP),
주황버섯(13 HP), 초록버섯(24 HP)입니다. 방어력은 0이며 레벨 1에서 어떤 무기라도
앞의 네 몬스터는 1회 명중, 초록버섯은 2회 명중으로 처치하도록 설정했습니다.
120초 이후 상위 등급 몬스터들이 등장합니다.

8분 동안 생성 가능한 일반 몬스터의 이론적 총합은 약 1,880마리이며
(빠짐없이 처치하고 최대 210마리 동시 제한에 걸리지 않는 가정),
실제 처치 수와 레벨업 횟수는 무기·선택·전투 방식에 따라 달라집니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`은 `main`에 Push할 때 테스트와 빌드를 실행하고,
성공한 결과만 GitHub Pages에 올립니다. Pull Request에서는 테스트와 빌드만 합니다.
배포 작업에는 GitHub Actions의 Pages 권한과 OIDC가 사용되며 별도 비밀값을 추가하지 않습니다.

최초 설정:

1. 게임 전용 GitHub 저장소를 만듭니다. 공개 저장소에 Push하면 게임 코드, 이미지와
   Git 이력이 공개됩니다. 이미지 출처와 권리 정보는 `ASSET_SOURCES.md`를 확인하세요.
2. 이 게임 저장소에 GitHub 원격을 연결하고 `main`을 Push합니다. 개인 Git 인증이 필요한
   경우 Git Credential Manager의 로그인 창에서 직접 로그인합니다. 토큰이나 비밀번호를
   명령행, 환경변수 또는 파일에 직접 넣지 않습니다.
3. GitHub 저장소의 **Settings → Pages → Build and deployment → Source**를
   **GitHub Actions**로 선택합니다. 설정이 Push 후에 이뤄졌다면 Actions 탭에서
   `Verify and deploy game`을 수동 실행하거나 이후 `main`에 Push합니다.
4. Actions 실행이 성공하면 Pages 설정 또는 해당 배포 작업에 표시된 URL로 접속합니다.

기존 `chatgpt.site`는 별도 호스팅이므로 GitHub Pages가 갱신해 주지 않습니다.
테스트 통과와 Push 성공, GitHub Actions 실행 성공, 실제 사이트 접속은 각각 별도로 확인해야 합니다.
